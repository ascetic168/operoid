# 第十九章 — Tool SDK 工具介面

版本：0.1
狀態：草稿

> 本章定義每個 Tool 都必須遵守的**介面**。
> 沒有程式語言。沒有特定協定。重要的是契約。

---

## 1. 目的

Tool SDK 是 **Employee 與 Tool 之間的契約**。

它定義一個 Tool 必須暴露什麼，才能在 Emploid 之內被使用，以及 Runtime 在一次 Tool 調用周圍做出哪些保證。透過固定這份契約，系統讓 Tool 撰寫一次就能被任何被授權的 Employee 使用 —— 也讓新型態的 Tool（新的驅動器、新的協定）得以加入，而不必改動使用它們的 Employee。

不遵守這份契約的能力，不是 Tool。它是一個不受治理的風險。

---

## 2. Tool 介面

每個 Tool 都必須暴露：

```
Tool
│
├── Spec          — 一份完整的描述（見第八章）
├── Execute()     — 給定被允許的輸入，執行操作
└── （隱含）       — 回傳一個結果，或一個結構化的錯誤
```

- **Spec** 是強制且完整的：目的、權限、輸入、輸出、逾時、重試、紀錄。一份沒有完整 Spec 的 Tool，會在登記時被拒。
- **Execute** 是唯一的作業。它接受符合 Spec 的輸入，執行操作，並回傳一個結果或一個結構化的錯誤。

一個 Tool 恰好有一個作業面：Execute。如果一個能力需要許多作業，它就是許多個 Tool，各自有自己的 Spec。

---

## 3. Tool 必須遵守的契約

為了被信任，每個 Tool 都遵守：

- **執行前檢查權限。** Runtime 驗證調用的 Employee 是否被授權；Tool 絕不繞過這一步。
- **依 Spec 驗證輸入。** 任何在宣告契約之外的事物都被拒。
- **強制逾時。** 一個跑太久的 Execute 會被放棄，不會被允許永遠跑下去。
- **暫時性失敗會重試 —— 然後被回報。** 重試政策是 Spec 的一部分；當重試耗盡，回傳一個結構化的錯誤。
- **每次調用都被紀錄。** 呼叫了什麼、由誰、用什麼輸入、結果為何 —— 以一個 Event 記錄下來。

---

## 4. Tool 不得做的事

一個 Tool 不得：

- **依自身判斷決定是否行動。** 它在合法請求時執行；在非法或未授權請求時拒絕。它不選擇。（原則 5。）
- **超出其宣告的 Spec。** 沒有隱藏輸入，沒有未記載的副作用。
- **持有 Employee 的職權。** Employee 帶來職權；Tool 帶的是「可被調用」的權限。
- **隱藏失敗。** 錯誤必須被回傳，不能被吞掉。

一個違反這些的 Tool，不是一個行為不端的 Tool —— 它是一個被錯誤分類的 Employee，也是一個安全問題。

---

## 5. 工具驅動器

Tool 透過**驅動器** 接觸外界，每一種都遵守同一份 Tool 介面：

```
Tool driver
├── Local       — 平台內建
├── Protocol    — 外部工具協定伺服器
├── Service     — 遠端 HTTP 風格 API
├── Database    — 可查詢的資料庫
├── Code        — 執行腳本或程式的執行環境
└── Native      — 直接的平台整合
```

驅動器是實作細節。對 Employee 與 Runtime 而言，每個 Tool 看起來都一樣：一份 Spec 與一個 Execute。

---

## 6. 未來擴展

Tool SDK 未來可能支援：

- **串流執行** —— 為漸進式產出結果的 Tool 而設。
- **組合** —— 宣告一個 Tool 去編排其他 Tool，而它本身仍是一個單純、可決策的 Tool。
- **動態 Spec 發現** —— 一個 Tool 在連線時廣播自己的 Spec。
- **預算與配額** —— 透過 SDK 強制的、每個 Employee 對昂貴 Tool 的使用限制。
