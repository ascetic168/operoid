# 第十六章 — Message 訊息

版本：0.1
狀態：草稿

> Message 是互動的介面，不是工作的歸宿。工作的耐久產出仍是 Artifact；長期責任仍是 Commitment。

---

## 1. 目的

Message 是**人類與 Employee 之間一趟對話往返的紀錄**——一段有方向（人類→員工，或員工→人類）的文字。

Operoid 刻意不是一個聊天應用程式：工作不該埋沒在對話裡（原則 3）。但人類與 Employee 協作（目標 4）需要一個互動層——人類下達指示、Employee 回覆或主動發問。Message 承載這些**互動本身**，而互動所觸發或產出的耐久結果，仍分別落地為 Task（待辦）、Artifact（產出）與 Commitment（責任）。

Message 解決兩件事：(a) 員工需要能對人類**說話**——回覆、反問、提案；(b) 這些往返需要被保留為可回顧的互動紀錄，而不只是變成 Inbox 裡的 Task 後就消失。

---

## 2. 職責

一則 Message 對以下事項負責：

- **承載一段往返文字** —— 這一趟說了什麼。
- **標示方向** —— 是人類→員工，或員工→人類。
- **加蓋時間戳** —— 何時發生。
- **可選地關聯** —— 指向它觸發的 Commitment，或附帶的 Artifact。

---

## 3. 擁有

一則 Message 擁有：

- 它的**方向** —— In（人類→員工）或 Out（員工→人類）。
- 它的**文字內容**。
- 它的**時間戳**。
- 它的**關聯** ——（可選）所屬 Commitment、（可選）附帶的 Artifact。

---

## 4. 不擁有

一則 Message **不**擁有：

- **工作本身** —— 那是 Task／Artifact／Commitment 的事。Message 是觸發與回顧的介面，不是工作的容器。
- **耐久性** —— Message 是互動紀錄，可被整理、摘要或修剪；它不像 Artifact 是永久的成果。一段重要對話的結論應晉升為 Artifact 或 Commitment。
- **決策** —— Message 陳述互動，不做判斷。

Message 是互動的介面，不是工作的歸宿。

---

## 5. 生命週期

```
Sent → Seen（被收件方讀取）→（可選）晉升為 Artifact／Commitment → Pruned
```

- **Sent（發出）** —— 由人類（In）或 Runtime 代員工（Out）產出。
- **Seen（已讀）** —— 被收件方讀取（人類在 UI 看見；員工在下一次喚醒時讀取）。
- **晉升** —— 若一趟往返的結論是耐久的，它應被晉升為 Artifact（成果）或 Commitment（責任）。Message 本身不留作永久紀錄。
- **Pruned（修剪）** —— 互動紀錄可被摘要或清理，以維持可讀性。

---

## 6. 與既有概念的關係

- **Inbox／Task**：人類的 Message（In）會成為員工 Inbox 裡的一個 Task（Message-driven Trigger，Ch.12），喚醒員工。Message 保留了「互動紀錄」這一面；Task 是「工作項」這一面——同一趟往返的兩種視角。
- **Event**：員工也可以用 Event（Ch.14）記錄「發生了某事」；但 Event 是不可變歷史、不期待回應。Message 是**期待往返的互動**——員工的 Out Message 可能是一個等待人類回覆的提問。
- **Artifact**：若一趟互動產生了耐久成果，那是 Artifact（Ch.06），Message 只是觸發它的互動。一行字的簡短回覆，留作 Message 即可，不必晉升。

---

## 7. 未來擴展

- **群聊** —— 多人類／多員工的共享對話。
- **結構化訊息** —— 帶型別承載的訊息（如表單、選項），超越純文字。
- **保留政策** —— 不同 Message 類型的保留與摘要規則。
