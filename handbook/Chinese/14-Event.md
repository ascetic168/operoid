# 第十四章 — Event 事件

版本：0.1
狀態：草稿

---

## 1. 目的

Event 是**某件事已發生的不可變紀錄**。

一個 Employee 提交了一份 Artifact。一個 Tool 被調用。一個 Commitment 被滿足。一個 Trigger 觸發。這其中每一件都是一個 Event —— 一個加蓋時間戳、被系統記住的事實。

Event 是讓 Operoid 各部分保持解耦的骨幹。Trigger 監看 Event；Runtime 記錄 Event；稽核與指標都從 Event 建立而來。因為 Event 是不可變的，它們構成工作空間所做一切的可信歷史。

---

## 2. 職責

一個 Event 對以下事項負責：

- **陳述一個事實** —— 發生了什麼，毫不含糊。
- **承載它的上下文** —— 誰參與、影響了什麼、以及相關細節。
- **加蓋時間戳** —— 何時發生。
- **不可變** —— 一旦記錄，絕不更改。

Event 描述過去。它不指揮未來。

---

## 3. 擁有

一個 Event 擁有：

- 它的**類型** —— 發生事物的類別。
- 它的**承載（payload）** —— 專屬於此次發生的細節。
- 它的**時間戳** —— 何時發生。
- 它的**來源** —— 哪個 Employee、Tool、Trigger 或系統產出它。
- 它的**不可變性** —— 發出之後無法編輯。

### Event 的種類

```
Event
├── Lifecycle      （某個 Employee 喚醒、睡眠、出錯）
├── Domain         （一張訂單抵達、一件客訴結案、一個期限到達）
├── Tool           （一個 Tool 被調用、成功或失敗）
├── Artifact       （一份成果物被提交、修訂、取代）
└── System         （工作空間啟動、暫停、封存）
```

---

## 4. 不擁有

一個 Event **不**擁有：

- **它所描述的動作** —— 動作已經發生；Event 只是記錄它。
- **對它的反應** —— 反應是 Trigger 與 Employee 的工作。
- **決策** —— Event 是事實，不是判決。

Event 是歷史，不是指令。

---

## 5. 生命週期

```
Emitted → Stored → Consumed (by Triggers, audits, metrics) → Archived
```

- **Emitted（發出）** —— 在某件事發生的那一刻，由系統的某部分產出。
- **Stored（儲存）** —— 附加到工作空間的不可變紀錄。
- **Consumed（消費）** —— 被 Trigger（可能進而喚醒 Employee）、稽核軌跡與指標讀取。
- **Archived（封存）** —— 作為工作空間對自身的記憶，長期保留。

Event 是只能附加的（append-only）。更正是透過發出一個新的 Event 來完成，絕不是透過編輯舊的。

---

## 6. 未來擴展

Event 概念未來可能支援：

- **事件溯源（Event sourcing）** —— 透過重播某個物件的 Event，重建該物件的狀態。
- **串流** —— 即時消費，用於即時監控與儀表板。
- **跨工作空間事件** —— 受控地將 Event 發布到聯邦工作空間。
- **保留政策** —— 不同 Event 類型要保留多久的規則。
