# 第八章 — Tool 工具

版本：0.1
狀態：草稿

> Tool 是能力。它絕不是決策者。

---

## 1. 目的

Tool 把**外部能力**暴露給 Employee。

Employee 能推理，但光推理改變不了任何事。要對世界採取行動 —— 寄一封信、查一筆資料、跑一段計算、操作一套設計工具、呼叫一個外部服務 —— Employee 必須調用一個 Tool。

Tool 是 Emploid 跨越自身邊界的方式。它們是 Employee 的手與眼。但就像手一樣，它們不選擇要抓什麼。由 Employee 選擇；由 Tool 去抓。

---

## 2. 職責

一個 Tool 對以下事項負責：

- **在被調用時執行單一、定義明確的操作**。
- **遵守它的契約** —— 接受的輸入與回傳的輸出。
- **尊重權限** —— 拒絕任何調用它的 Employee 未被授權的事。
- **行為可預期** —— 逾時、重試與紀錄，是讓 Tool 值得信賴的一部分。

Tool 不決定*是否*行動。它在合法呼叫者請求時行動，在呼叫者缺乏職權時拒絕。

---

## 3. 擁有

每個 Tool 都擁有一份 **Tool Spec（工具規格）**，其中必須包含：

- **Spec** —— 這個 Tool 做什麼，白話描述。
- **Permission（權限）** —— 調用它需要什麼職權。
- **Input（輸入）** —— 接受的參數，含型別與限制。
- **Output（輸出）** —— 回傳什麼，包含錯誤情況。
- **Timeout（逾時）** —— 一次呼叫最多能跑多久才被放棄。
- **Retry（重試）** —— 暫時性失敗時會如何。
- **Logging（紀錄）** —— 每次調用要記下什麼。

這七項不是可選的。一份沒有完整 Tool Spec 的能力，還不是 Tool —— 它是一個不受治理的風險。

### 工具驅動器

Tool 透過不同種類的**驅動器（driver）** 接觸外界：

```
Tool
├── Local Tool        （本地工具）
├── Protocol Tool     （外部工具協定伺服器）
├── REST / Service    （HTTP 風格 API）
├── Database          （可查詢的資料庫）
├── Code Runtime      （執行腳本或程式）
└── Native            （平台內建）
```

任何特定的協定或技術，都**只是其中一種驅動器**。架構不依賴其中任何一個；它只依賴 Tool Spec。

---

## 4. 不擁有

一個 Tool **不**擁有：

- **決策** —— 它從不選擇何時或是否行動。（原則 5。）
- **結果的責任** —— 那屬於調用它的 Employee。
- **職權** —— Tool 帶有 permission（權限），但 authority（職權）是由 Role 授予 Employee 的。
- **自身的狀態記憶** —— Tool 可以是無狀態的；任何狀態都屬於它所包裝的外部系統。

一個開始做決策的 Tool，已不再是 Tool。它已變成一個未經授權的 Employee。

---

## 5. 生命週期

```
Registered → Enabled → Disabled → Deprecated → Retired
```

- **Registered（登記）** —— 其 Spec 已為工作空間所知。
- **Enabled（啟用）** —— 在權限允許下，可供 Employee 調用。
- **Disabled（停用）** —— 暫時關閉；調用被拒。
- **Deprecated（棄用）** —— 即將移除；Employee 應遷移他處。
- **Retired（退役）** —— 已移除；為歷史保留 Spec。

---

## 6. 未來擴展

Tool 概念未來可能支援：

- **動態發現** —— 自動偵測新可用的 Tool 並登記其 Spec。
- **組合** —— 把多個 Tool 串接成更高層的能力，同時讓每個 Tool 保持單純且可決策。
- **市集市場** —— 跨 Workspace 發布 Tool Spec 以供重用。
- **可觀測性** —— 對每個 Tool 如何、多頻繁、多成功地被使用，提供更豐富的遙測。
- **配額與預算** —— 限制 Employee 對昂貴 Tool 的使用。
