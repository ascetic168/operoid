# 第十五章 — Memory 工作記憶

版本：0.1
狀態：草稿

> 上下文是被恢復的，而非被記住。（原則 8。）

---

## 1. 目的

Memory 是 Employee 的**工作上下文** —— 它的工作循環中*此刻* 正在發生什麼的暫存區。

它刻意與另外兩個常被混淆的事物區分開來：

- **Knowledge** 是組織經策展、持久的專長（第七章）。
- **Brain 的長期記憶** 是隨 Brain 累積的經驗（第五章）。

Memory 不是這兩者。Memory 是短期的、運作性的、專屬於一個 Employee 的：今天聯絡了誰、供應商答應了什麼、主管要求優先處理什麼、什麼還在等待中。它的存在，是為了讓 Employee 在一次休眠後能接續工作，而不會失去進度。

---

## 2. 職責

Memory 對以下事項負責：

- **承載當前循環的上下文** —— Employee 繼續工作所需的事實。
- **在休眠時被持久化** —— 讓進行中的事物不會流失。
- **在喚醒時被恢復** —— 讓 Employee 精確地從它中斷之處繼續。
- **保持有界** —— 工作記憶是暫存區，不是檔案庫。

---

## 3. 擁有

一個 Employee 的 Memory 擁有：

- **近期的互動** —— 當前工作循環中發送與接收的訊息。
- **待辦的後續** —— 等待回覆或結果的事物。
- **暫時的筆記** —— 尚未提交到別處的觀察與意圖。
- **指標** —— 指向當前涉及的 Commitment、Task 與 Artifact。

Memory 屬於單一 Employee。它不共享，因為沒有兩個 Employee 共享相同的工作上下文。

---

## 4. 不擁有

Memory **不**擁有：

- **持久的知識** —— 那屬於知識庫與 Brain。
- **長期的經驗** —— 那屬於 Brain。
- **已提交的成果** —— 那些屬於 Artifact。
- **其他 Employee 的上下文** —— 每個 Employee 的 Memory 是它自己的。

無止盡增長的工作記憶，是設計錯誤。本該持久卻被遺忘的 Memory，是 bug。邊界在於：**如果某件事必須存活到這個工作循環之後，就把它晉升為 Artifact、Commitment 或 Knowledge。**

---

## 5. 生命週期

```
(喚醒時) Restored ──► Execute 期間 Accumulates ──► (睡眠時) Persisted ──► (下次喚醒) Restored
                                                            │
                                                      Pruned / promoted
```

- **Restored（恢復）** —— 在喚醒時，Runtime 從已持久化的內容重建 Employee 的 Memory。
- **Accumulates（累積）** —— 在執行期間，Employee 記錄新的互動與筆記。
- **Persisted（持久化）** —— 在睡眠時，當前的 Memory 被儲存，讓下一次喚醒無縫。
- **Pruned / Promoted（修剪／晉升）** —— 不再相關的項目被丟棄；長期重要的項目被晉升到它們該屬於的 Artifact、Commitment 或 Knowledge。

Memory 是會周轉的。一個健康的 Employee，其工作記憶是小的、當下的、聚焦於手頭工作的。

---

## 6. 未來擴展

Memory 概念未來可能支援：

- **智慧晉升** —— 自動建議何時某則工作筆記該成為知識或成果物。
- **摘要** —— 把一段長工作循環壓縮成一個精簡、可恢復的上下文。
- **選擇性召回** —— 只恢復與到來的 Task 相關的 Memory 切片。
- **委派時的記憶共享** —— 在工作被委派時，把某個 Employee 相關的 Memory 切片交給另一個。
