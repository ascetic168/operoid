# 企業版三種角色介面

> 適用版本：v0.5.11。部署完成後（見[第 04 章](04-install-enterprise.md)），瀏覽器開啟 `https://<伺服器IP>:7340/` 即三個前端的入口頁。介面語言：繁體中文／简体中文／English。

## 角色

| 角色 | 定位 | 入口 |
|---|---|---|
| **admin** | 系統管理者：帳號、模板、技能、知識、橋接、版本 | `/admin` |
| **manager** | 經理人：審核提案、監督營運、知識治理 | `/manager` |
| **user** | 一般使用者：擁有自己的員工並日常使用 | `/user` |

權限**向下包含**：admin ⊃ manager ⊃ user（端點級 RBAC）。master token 是結構性的 admin，僅供開通與服務間整合。

登入為密碼制：首次登入**強制設定新密碼**（≥8 碼）；連續 5 次失敗鎖定 15 分鐘。

## `/admin` 管理者介面

| 頁面 | 做什麼 |
|---|---|
| **總覽** | 系統現況；版本卡（檢查更新；氣隔環境可關閉檢查，見[第 15 章](15-service-and-updates.md)） |
| **帳號管理** | 建立／停用／啟用帳號、指派角色、重設密碼（臨時密碼僅顯示一次） |
| **知識授權** | 知識政策、principals 與 token、TTL grants、知識範圍——同[第 13 章](13-governance.md) |
| **AI 員工模板** | 全組織的員工模板 CRUD |
| **腦與前置檢查** | 註冊腦、設定模型；前置元件狀態 |
| **技能庫** | 管理公司共用庫；把個人區技能**晉升**為組織共用 |
| **郵件橋接** | email 通道的設定表單（對應 `obridge.toml`，見[第 14 章](14-email-bridge.md)） |

## `/manager` 經理人介面

| 頁面 | 做什麼 |
|---|---|
| **營運儀表板** | 團隊員工與營運現況 |
| **收件匣** | 待核可提案（承諾、技能提案）、異常員工——同[第 10 章](10-inbox-and-events.md) |
| **技能庫** | 審核技能提案；採用技能 |
| **知識治理** | 發放／撤銷 TTL grants（有時效的越級知識授權） |
| **營運主控台** | 知識檢索操作（可被 `ops_retrieval_enabled=false` 停用——檢索一律走員工工具） |
| **事件流** | 生命週期事件；點員工可進入對話 |

## `/user` 一般使用者介面

| 頁面 | 做什麼 |
|---|---|
| **我的員工** | 招募模板、部署實體、對話——個人版「員工模板／員工實體」的網頁版 |
| **知識查詢** | 以受治理的方式直接問腦 |
| **收件匣** | 提案核可、異常員工 |
| **技能庫** | 瀏覽技能圖書館並「加入」個人區、提交技能提案 |
| **工廠** | 拖放文件入知識庫——個人版工廠的網頁版 |
| **事件流** | 自己員工的生命週期事件 |

自 v0.5.9 起，使用者主控台也能與**同事的**員工對話（權限仍受知識政策約束）。

## 與個人版的功能對照

| 功能 | 個人版（桌面） | 企業版（網頁） |
|---|---|---|
| 員工模板／實體 | 同一頁面兩頁 | admin 管模板；user 部署實體 |
| 技能提案流程 | 收件匣核可 → 進個人區 | user 提案 → manager/admin 核可 → **admin 晉升**共用庫 |
| 知識授權 | 「設定 → 知識授權」 | admin「知識授權」＋manager「知識治理」 |
| 工廠 | 桌面 | user「工廠」 |
| Claude Code handoff | 內建（可讀寫整顆腦） | 預設退役（`claude_code_handoff_enabled=false`）——企業場景不應依賴此通道 |
| 更新 | App 內建更新 | 版本卡提示＋手動升級 |
