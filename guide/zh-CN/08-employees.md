# 员工管理：模板与实体

> 适用版本：v0.5.11。员工功能需先开启「设置 → 应用程序 → 启用 Agent-OS」。概念阅读：[架构手册 Ch.04 员工](../../handbook/Chinese/04-Employee.md)。

## 两层模型：模板 → 实体

- **员工模板**——职务的定义：对应哪颗脑、职责描述、允许用哪些工具。可重用。
- **员工实体**——从模板部署出的「那位员工」：独立的名字、独立的状态与历史。一个模板可部署多个互不干扰的实体。

## 员工模板（「员工模板」页）

按「新增模板」：

| 字段 | 说明 |
|---|---|
| 名称 | 例如「采购助理」 |
| 对应脑 | 这类员工查证作答的知识来源（一个模板对应一个脑） |
| 角色（选填） | 机器可读的角色代号，例如 `procurement` |
| 职责描述（选填） | 部署时复制到每个实体的职说明，例如「负责周报汇总与供应商询问」 |
| 工具授权 | **未勾选的工具员工看不到**——这是最基本的委任界线 |

### 工具授权

- **默认集**：think（深思）／search（检索）／send（沟通）——知识与沟通的基本组合。
- **允许写入笔记**：员工可将产出写到专属产出目录（默认 `~/employee-output`，不入图谱；人工审阅后移入来源 repo 走 sync 晋升）。
- **允许读取／写入／编辑工作区文件**：报告草稿、CSV 等自有工作区内容；编辑为精确字符串替换（须先读取）。
- **允许执行工作区命令**（高级）：数据处理、跑公司脚本——给予前请审慎评估。

模板可重命名、删除；「模板详情」可查看创建时间与设置。

## 员工实体（「员工实体」页）

「部署新实体」：选来源模板、填实体名称（例如 `Steve@TW`）、可填对外 email（供[邮件桥接](14-email-bridge.md)路由）。

实体卡片上**按右键**管理：

| 动作 | 说明 |
|---|---|
| 对话… | 打开聊天（见下节） |
| 沟通… | 发一则消息给这位员工（它会被唤醒处理） |
| 监看… | 打开监看面板（见下节） |
| 交办… | 建立承诺：给**承诺标题**（如「追踪蚀刻良率事件到结案」）与**完成条件**（如「产出含行动时间表与财务影响的报告」）——建立后员工立即醒来，工作到完成 |
| 打开产出目录 | 打开此员工的输出文件夹 |
| 重命名／删除实体 | — |
| 封存… | 历史（对话／事件／产出）保留、不再被唤醒；随时可「解除封存」。已封存员工集中在清单下方，可追溯 |

## 对话

- 你看得见它工作：提问与 Markdown 回复之间，列出**每个工具调用**——工具名、参数、耗时；回答以串流方式即时输出。
- 「{n} 个工具调用」可展开查看完整轨迹；「思考中」表示正在推理。
- **清除对话**只清消息——工作产出（Artifact）与承诺（Commitment）保留。
- 员工工作中按「停止」是**合作式停止**：在下一个步骤边界优雅停止；再传消息或交办即可恢复。

## 监看面板

「监看…」打开这位员工的即时仪表板：

- **待核可提案**／**自动启用（登记类别）**——哪些行动在等你、哪些依登记表自动启用；
- **抽审**——对自动启用的承诺标记「归类正确／归类错误」，喂给分歧率统计；
- **进行中的承诺、目前工作、近期产出、生命周期事件、已决策承诺、已完成工作**。

## 子代理

自 v0.5.7 起，员工可派生**子代理（spawn_subagent）**：一次性的只读研究上下文，用来查资料、读文件后把结论带回父任务——不能写任何东西。步数保险丝默认 20 步（`subagent_max_steps`，见[第 17 章](17-config-reference.md)）。

## 员工之间的沟通

员工之间有内部邮箱（可互通消息、查同事名单），由「设置 → 应用程序」的 `internal_mail_enabled` 总开关控制（默认开；关闭＝工具不存在）。企业版里，用户也能从自己的主控台与**同事的**员工对话（自 v0.5.9 起）。
