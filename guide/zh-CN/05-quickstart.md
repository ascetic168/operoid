# 快速上手

> 适用版本：v0.5.11。前提：已依[第 03 章](03-install-personal.md)安装个人版，且[前置组件](02-requirements.md)（git／bun／gbrain）已就绪。全程约 15 分钟。

## 1. 启动 Operoid

打开桌面应用。它会自动带起本地服务（oserver，`127.0.0.1:7340`）——若出现「缺少前置程序」对话框，先依[第 02 章](02-requirements.md)补齐再回来。

## 2. 开启 Agent-OS

员工功能目前藏在功能开关后面：到「设置 → 应用程序」，勾选**「启用 Agent-OS（员工模板／实体管理）」**。没开的话，「员工模板」「员工实体」两页会提示 Agent-OS 未开启。

## 3. 设置模型与 API key

到「设置 → 模型」（GBrain 的 `config.json` 是权威来源，这里的控件会直接写入）：

1. **主模型**：填 `provider:model` 格式，例如 `zhipu:glm-5.3-flash`（provider 前缀决定用哪家 API）。它会同步应用到对话与四个内部分级任务。
2. **API key**：到对应 provider 申请，设成环境变量（`ZHIPUAI_API_KEY`、`ANTHROPIC_API_KEY`、`OPENAI_API_KEY` 等——完整清单见[第 17 章](17-config-reference.md)），**设好后重启 Operoid**。模型页会显示「API key 已设／缺 API key（环境变量）」。
3. 若要用知识检索，确认嵌入服务（llama-server）已在 `127.0.0.1:8080` 常驻——启动指令见[第 02 章](02-requirements.md)。

## 4. 准备一颗脑

到「脑」页：

- 第一次使用：按「新增」→「建立新脑（gbrain init）」，取名即可（新建脑的 embedding 模型默认 `llama-server:embeddinggemma-2`）。
- 按「设为活动」；再到「来源（sources）」按「新增来源」，登记一个 git repo 当知识来源（工厂写入与 sync 的对象）。

什么是脑、它跟 RAG 有何不同——见[附录 A](appendix-a-gbrain.md)；界面细节见[第 07 章](07-brains-and-models.md)。

## 5. 建立员工模板

到「员工模板」页按「新增模板」：

- **名称**：例如「采购助理」。
- **对应脑**：选刚刚的脑——每位员工经由它查证作答。
- **职责描述**（选填）：会复制到每个实体，例如「负责周报汇总与供应商询问」。
- **工具授权**：未勾选的工具员工看不到。默认集含 think（深思）／search（检索）／send（沟通）；要不要让它读写工作区文件、执行指令，由你决定——**这是最基本的委任界线**。

## 6. 部署实体

到「员工实体」页按「部署新实体」：选来源模板、取名（例如 `Steve@TW`）。模板是职务定义，实体才是那位「员工」——同一模板可以部署多个互不干扰的实体。

## 7. 第一次对话

在实体卡片上按**右键 →「对话…」**，发一则消息。你会看到它工作：提问与回复之间列出每个工具调用——调用了什么、参数、花了多久。

## 8. 交办第一个承诺

右键 →**「交办…」**：给一个承诺标题（例如「整理本周供应商报价变化」）与完成条件（例如「产出含比较表的报告」）。员工会醒来朝目标工作。

依「从严预设」，超出它授权的行动不会直接执行——它会**提案**到「待办」页等你核可。到「待办」看看：核可或拒绝，并可在「事件」页看到它的生命周期活动。
