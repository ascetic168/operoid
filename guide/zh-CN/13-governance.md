# 治理：登记表与知识授权

> 适用版本：v0.5.11。Operoid 的核心主张是把治理做成架构：**委任界线**（员工能做什么）由动作类别登记表管，**知识界线**（员工能知道什么）由知识授权管。理论源头见[界线的形状](../../journal/界线的形状_朱国栋.pdf)与[架构手册 Ch.20](../../handbook/Chinese/20-Security.md)。

## 动作类别登记表（「设置 → 登记表」）

画线权的画布：登记哪些**承诺类别**可免个案核可自动启用。

### 从严预设

**未登记的类别一律送人类核可。** 收紧永远允许；放宽必须付出代价——具名问责、未来届期与放宽证据，缺一存档被拒。授权以**动作类别**为单位，绝不授权给「系统」；事故后自动冻结。

### 委任三层

| 层 | 谁决定 | 入场条件 |
|---|---|---|
| **人裁决层** | 员工提案，人类核可并签署后才执行 | 不可逆、影响触及客户／支出／安全／权利，或无法指名问责者 |
| **围栏自动层** | 员工在工具白名单围栏内直接执行，人类抽审 | 可逆＋内部影响＋具名问责＋未来届期＋放宽证据 |
| **有主自动层** | 员工例行执行；人类保留问责与紧急停止权 | 围栏层条件＋高度例行＋紧急停止机制 |

### 每个类别登记什么

- **类别 id 与归类准则**——什么样的承诺属于这一类。
- **三问**：可逆？影响范围（内部／客户／支出／安全／权利）？问责人（具名的人类负责人）？
- **届期（重签日）**——授权会过期；届期未重签的类别不再自动启用（界面会列出「已届期」警示）。
- **抽审比例**——1.0＝全数送人类抽审；抽审结果（归类正确／错误）在员工监看面板标记。
- **放宽证据**——凭什么放宽（例如某次实测记录）。
- **围栏**：工具白名单（**只能缩限、不能放宽**员工本身的允许清单）、禁对外发送、仅限模板。
- **紧急停止机制**（有主自动层必填）——如何立即停止，例如「关闭 Obridge 通道」。

### 全局保险丝与预算

| 设置 | 默认 | 作用 |
|---|---|---|
| **保险丝关键字** | （空） | 承诺标题或条件含任一关键字，凌驾类别层级、强制送人类核可；清空＝停用 |
| **每周提案预算** | 不设限 | 每周可自动启用的提案数上限 |
| **抽审分歧门槛** | 0.2 | 近 30 天抽审分歧率超过此值即发警报（登记表页会显示目前分歧率） |

实务建议：先让系统跑在从严预设一至两周，把**重复出现、低风险、有具名负责人**的行动归纳成类别，才登记放宽；高风险类别就让它留在人裁决层。

## 知识授权（「设置 → 知识授权」）

员工能知道什么，由四个部分管理：

### 知识政策（规则）

规则依优先序先到先得：**DENY 命中即拒 → ALLOW 命中即准 → 无匹配＝拒（fail closed）**。规则字段：principals、scopes、等级、部门（皆可 CSV 多值）。

**保密等级是硬天花板**——超过 clearance 的范围，任何规则与 grant 都打不开。政策的权威在 Operoid；GBrain 只见 source 分区。

### Principals 与 API token

每个 principal（人、服务、员工）可签发 API token；**明文只显示一次**——关闭对话框后无法再取，可轮替、可撤销。

### 临时授权（TTL grants）

短期任务需要越级访问时，发放**有时效**的 grant（以小时计），到时自动失效，可随时撤销。

### 知识范围（scopes）

scopes→sources 的映射（只读）：部门、项目如何对应到脑里的来源。

## 检索收据（Retrieval Receipt）

每一次特权检索都留下一张收据：**谁、在哪个任务、依哪版政策、看到哪些**。事后审计不是翻日志猜，而是查收据。

## 文件外流的 egress 分层

文件转换（复杂 PDF → MinerU）也受治理：`allow_public_egress` 默认**关**——送到公共第三方云（如 mineru.net 云端解析）须明确开启；自建的私人端点（`mineru_remote_url`）不受此闸连坐（设置本身即同意）。Claude Code handoff 通道可用 `claude_code_handoff_enabled=false` 整个退役（企业模式的建议），见[第 12 章](12-knowledge.md)。
