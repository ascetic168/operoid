# 企业版三种角色界面

> 适用版本：v0.5.11。部署完成后（见[第 04 章](04-install-enterprise.md)），浏览器开启 `https://<服务器IP>:7340/` 即三个前端的入口页。界面语言：繁体中文／简体中文／English。

## 角色

| 角色 | 定位 | 入口 |
|---|---|---|
| **admin** | 系统管理员：账号、模板、技能、知识、桥接、版本 | `/admin` |
| **manager** | 经理人：审核提案、监督运营、知识治理 | `/manager` |
| **user** | 普通用户：拥有自己的员工并日常使用 | `/user` |

权限**向下包含**：admin ⊃ manager ⊃ user（端点级 RBAC）。master token 是结构性的 admin，仅供开通与服务间整合。

登录为密码制：首次登录**强制设置新密码**（≥8 位）；连续 5 次失败锁定 15 分钟。

## `/admin` 管理员界面

| 页面 | 做什么 |
|---|---|
| **总览** | 系统现况；版本卡（检查更新；气隔环境可关闭检查，见[第 15 章](15-service-and-updates.md)） |
| **账号管理** | 创建／停用／启用账号、指派角色、重设密码（临时密码仅显示一次） |
| **知识授权** | 知识政策、principals 与 token、TTL grants、知识范围——同[第 13 章](13-governance.md) |
| **AI 员工模板** | 全组织的员工模板 CRUD |
| **脑与前置检查** | 注册脑、设置模型；前置组件状态 |
| **技能库** | 管理公司共用库；把个人区技能**晋升**为组织共用 |
| **邮件桥接** | email 通道的设置表单（对应 `obridge.toml`，见[第 14 章](14-email-bridge.md)） |

## `/manager` 经理人界面

| 页面 | 做什么 |
|---|---|
| **运营仪表板** | 团队员工与运营现况 |
| **收件匣** | 待核可提案（承诺、技能提案）、异常员工——同[第 10 章](10-inbox-and-events.md) |
| **技能库** | 审核技能提案；采用技能 |
| **知识治理** | 发放／撤销 TTL grants（有时效的越级知识授权） |
| **运营主控台** | 知识检索操作（可被 `ops_retrieval_enabled=false` 停用——检索一律走员工工具） |
| **事件流** | 生命周期事件；点员工可进入对话 |

## `/user` 普通用户界面

| 页面 | 做什么 |
|---|---|
| **我的员工** | 招募模板、部署实体、对话——个人版「员工模板／员工实体」的网页版 |
| **知识查询** | 以受治理的方式直接问脑 |
| **收件匣** | 提案核可、异常员工 |
| **技能库** | 浏览技能图书馆并「加入我的技能区」、提交技能提案 |
| **工厂** | 拖放文件入知识库——个人版工厂的网页版 |
| **事件流** | 自己员工的生命周期事件 |

自 v0.5.9 起，用户主控台也能与**同事的**员工对话（权限仍受知识政策约束）。

## 与个人版的功能对照

| 功能 | 个人版（桌面） | 企业版（网页） |
|---|---|---|
| 员工模板／实体 | 同一界面两个页面 | admin 管模板；user 部署实体 |
| 技能提案流程 | 收件匣核可 → 进个人区 | user 提案 → manager/admin 核可 → **admin 晋升**共用库 |
| 知识授权 | 「设置 → 知识授权」 | admin「知识授权」＋manager「知识治理」 |
| 工厂 | 桌面 | user「工厂」 |
| Claude Code handoff | 内置（可读写整颗脑） | 默认退役（`claude_code_handoff_enabled=false`）——企业场景不应依赖此通道 |
| 更新 | App 内置更新 | 版本卡提示＋手动升级 |
