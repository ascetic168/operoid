# 快速上手

> 適用版本：v0.5.11。前提：已依[第 03 章](03-install-personal.md)安裝個人版，且[前置元件](02-requirements.md)（git／bun／gbrain）已就緒。全程約 15 分鐘。

## 1. 啟動 Operoid

開啟桌面應用。它會自動帶起本地服務（oserver，`127.0.0.1:7340`）——若出現「缺少前置程式」對話框，先依[第 02 章](02-requirements.md)補齊再回來。

## 2. 開啟 Agent-OS

員工功能目前藏在功能旗標後面：到「設定 → 應用程式」，勾選**「啟用 Agent-OS（員工模板/實體管理）」**。沒開的話，「員工模板」「員工實體」兩頁會提示 Agent-OS 未開啟。

## 3. 設定模型與 API key

到「設定 → 模型」（GBrain 的 `config.json` 是權威來源，這裡的控件會直接寫入）：

1. **主模型**：填 `provider:model` 格式，例如 `zhipu:glm-5.3-flash`（provider 前綴決定用哪家 API）。它會同步套用到對話與四個內部分級任務。
2. **API key**：到對應 provider 申請，設成環境變數（`ZHIPUAI_API_KEY`、`ANTHROPIC_API_KEY`、`OPENAI_API_KEY` 等——完整清單見[第 17 章](17-config-reference.md)），**設好後重啟 Operoid**。模型頁會顯示「API key 已設／缺 API key（環境變數）」。
3. 若要用知識檢索，確認嵌入服務（llama-server）已在 `127.0.0.1:8080` 常駐——啟動指令見[第 02 章](02-requirements.md)。

## 4. 準備一顆腦

到「腦」頁：

- 第一次使用：按「新增」→「建立新腦（gbrain init）」，取名即可（新建腦的 embedding 模型預設 `llama-server:embeddinggemma-2`）。
- 按「設為作用中」；再到「來源（sources）」按「新增來源」，登錄一個 git repo 當知識來源（工廠寫入與 sync 的對象）。

什麼是腦、它跟 RAG 有何不同——見[附錄 A](appendix-a-gbrain.md)；介面細節見[第 07 章](07-brains-and-models.md)。

## 5. 建立員工模板

到「員工模板」頁按「新增模板」：

- **名稱**：例如「採購助理」。
- **對應腦**：選剛剛的腦——每位員工經由它查證作答。
- **職責描述**（選填）：會複製到每個實體，例如「負責週報彙整與供應商詢問」。
- **工具授權**：未勾選的工具員工看不到。預設集含 think（深思）／search（檢索）／send（溝通）；要不要讓它讀寫工作區檔案、執行指令，由你決定——**這是最基本的委任界線**。

## 6. 部署實體

到「員工實體」頁按「部署新實體」：選來源模板、取名（例如 `Steve@TW`）。模板是職務定義，實體才是那位「員工」——同一模板可以部署多個互不干擾的實體。

## 7. 第一次對話

在實體卡片上按**右鍵 →「對話…」**，發一則訊息。你會看到它工作：提問與回覆之間列出每個工具呼叫——呼叫了什麼、參數、花了多久。

## 8. 交辦第一個承諾

右鍵 →**「交辦…」**：給一個承諾標題（例如「整理本週供應商報價變化」）與完成條件（例如「產出含比較表的報告」）。員工會醒來朝目標工作。

依「從嚴預設」，超出它授權的行動不會直接執行——它會**提案**到「待辦」頁等你核可。到「待辦」看看：核可或拒絕，並可在「事件」頁看到它的生命週期活動。
