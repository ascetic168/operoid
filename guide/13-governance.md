# 治理：登記表與知識授權

> 適用版本：v0.5.11。Operoid 的核心主張是把治理做成架構：**委任界線**（員工能做什麼）由動作類別登記表管，**知識界線**（員工能知道什麼）由知識授權管。理論源頭見[界線的形狀](../journal/界線的形狀_朱國棟.pdf)與[架構手冊 Ch.20](../handbook/Chinese/20-Security.md)。

## 動作類別登記表（「設定 → 登記表」）

畫線權的畫布：登記哪些**承諾類別**可免個案核可自動啟用。

### 從嚴預設

**未登記的類別一律送人類核可。** 收緊永遠允許；放寬必須付出代價——具名課責、未來屆期與放寬證據，缺一存檔被拒。授權以**動作類別**為單位，絕不授權給「系統」；事故後自動凍結。

### 委任三層

| 層 | 誰決定 | 入場條件 |
|---|---|---|
| **人裁決層** | 員工提案，人類核可並簽署後才執行 | 不可逆、影響觸及客戶／支出／安全／權利，或無法指名問責者 |
| **圍欄自動層** | 員工在工具白名單圍欄內直接執行，人類抽審 | 可逆＋內部影響＋具名問責＋未來屆期＋放寬證據 |
| **有主自動層** | 員工例行執行；人類保留問責與緊急停止權 | 圍欄層條件＋高度例行＋緊急停止機制 |

### 每個類別登記什麼

- **類別 id 與歸類準則**——什麼樣的承諾屬於這一類。
- **三問**：可逆？影響範圍（內部／客戶／支出／安全／權利）？問責人（具名的人類負責人）？
- **屆期（重簽日）**——授權會過期；屆期未重簽的類別不再自動啟用（介面會列出「已屆期」警示）。
- **抽審比例**——1.0＝全數送人類抽審；抽審結果（歸類正確／錯誤）在員工監看面板標記。
- **放寬證據**——憑什麼放寬（例如某次實測紀錄）。
- **圍欄**：工具白名單（**只能縮限、不能放寬**員工本身的允許清單）、禁對外發送、僅限模板。
- **緊急停止機制**（有主自動層必填）——如何立即停止，例如「關閉 Obridge 通道」。

### 全域保險絲與預算

| 設定 | 預設 | 作用 |
|---|---|---|
| **保險絲關鍵字** | （空） | 承諾標題或條件含任一關鍵字，凌駕類別層級、強制送人類核可；清空＝停用 |
| **每週提案預算** | 不設限 | 每週可自動啟用的提案數上限 |
| **抽審分歧門檻** | 0.2 | 近 30 天抽審分歧率超過此值即發警報（登記表頁會顯示目前分歧率） |

實務建議：先讓系統跑在從嚴預設一至兩週，把**重複出現、低風險、有具名負責人**的行動歸納成類別，才登記放寬；高風險類別就讓它留在人裁決層。

## 知識授權（「設定 → 知識授權」）

員工能知道什麼，由四個部分管理：

### 知識政策（規則）

規則依優先序先到先得：**DENY 命中即拒 → ALLOW 命中即准 → 無匹配＝拒（fail closed）**。規則欄位：principals、scopes、等級、部門（皆可 CSV 多值）。

**保密等級是硬天花板**——超過 clearance 的範圍，任何規則與 grant 都打不開。政策的權威在 Operoid；GBrain 只見 source 分區。

### Principals 與 API token

每個 principal（人、服務、員工）可簽發 API token；**明文只顯示一次**——關閉對話框後無法再取，可輪替、可撤銷。

### 臨時授權（TTL grants）

短期任務需要越級存取時，發放**有時效**的 grant（以小時計），到時自動失效，可隨時撤銷。

### 知識範圍（scopes）

scopes→sources 的映射（唯讀）：部門、專案如何對應到腦裡的來源。

## 檢索收據（Retrieval Receipt）

每一次特權檢索都留下一張收據：**誰、在哪個任務、依哪版政策、看到哪些**。事後稽核不是翻日誌猜，而是查收據。

## 文件外流的 egress 分層

文件轉換（複雜 PDF → MinerU）也受治理：`allow_public_egress` 預設**關**——送到公共第三方雲（如 mineru.net 雲端解析）須明確開啟；自架的私人端點（`mineru_remote_url`）不受此閘連坐（設定本身即同意）。Claude Code handoff 通道可用 `claude_code_handoff_enabled=false` 整個退役（企業模式的建議），見[第 12 章](12-knowledge.md)。
